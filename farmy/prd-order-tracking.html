PRD: Order Tracking Bottom Sheet — Homescreen

Product: Farmy App Feature: Order Tracking Bottom Sheet Scope: Farmy Internal Courier + External Courier Status: Draft Date: 2026-03-19

1. Feature Summary

A persistent bottom sheet on the Farmy app homescreen that surfaces the user's upcoming or active delivery at a glance. The sheet can be expanded for full detail or collapsed to a compact summary line. It reflects real-time delivery status, estimated delivery time, and live map visibility depending on where the courier is in the delivery lifecycle.

The goal is to reduce delivery-related support contacts and increase user confidence by keeping customers passively informed without requiring them to navigate away from the homescreen.

2. User Goals

As a... I want to... So that...
Farmy customer See my upcoming delivery time without opening the order details I can plan my day around my delivery
Farmy customer Know when the courier is en route or has arrived I can be ready to receive my order
Farmy customer Understand whether the time shown is exact or approximate I have accurate expectations about my delivery window

3. Scope

In scope

  • Farmy Internal Courier deliveries
  • External Courier deliveries
  • Bottom sheet shown on the app homescreen
  • Expanded and collapsed states
  • Status-driven display logic
  • Multilingual copy (EN, DE, FR)

Out of scope

  • Push notifications
  • Order details screen or order history
  • Technical implementation and API design (covered in separate tech spec)

4. Business Rules

4.1 When to Show the Bottom Sheet

The bottom sheet visibility is determined by a combination of order status and delivery status.

Order Status Delivery Status Bottom Sheet Shown?
Canceled Any No — hidden entirely
Complete unpacked Yes
Complete pending Yes
Complete en_route Yes
Complete arrived Yes
Complete shipped No — order is complete and removed from homescreen

4.2 Delivery Status States

Delivery Status Delivery Phase Map Shown? Notes
unpacked Not started No Time display depends on planned_delivery_time_is_fake
pending Not started No Time display depends on planned_delivery_time_is_fake
en_route Active delivery Only if courier is assigned planned_delivery_time_is_fake is always false in this state
arrived Active delivery No planned_delivery_time_is_fake is always false in this state
shipped Delivered — Bottom sheet is hidden

Map visibility rule: map is shown only when delivery status is en_route AND a courier is assigned. Both conditions must be true.

4.3 Time Display Logic

Two fields control how the delivery time is displayed:

  • planned_delivery_time — the time value to display
  • planned_delivery_time_is_fake (boolean) — indicates whether the time is exact or approximate
planned_delivery_time_is_fake Meaning What to Show
false or nil Exact delivery time is known Show planned_delivery_time as the exact expected arrival
true Exact time is unknown Show planned_delivery_time as the end-of-slot deadline ("before [Time]")

4.4 Polling / Refresh Interval

Condition Refresh Interval
Default (all other states) Every 20 minutes
planned_delivery_time_is_fake == false AND planned_delivery_time is today Every 1 minute

The high-frequency polling activates only when both conditions are met simultaneously. The switch itself does not trigger an immediate fetch — the next update still comes after the current 20-minute cycle completes. This is acceptable because these conditions are set early in the morning, well before the delivery window begins, so the lag has no practical impact on the user experience.

4.5 Copy / Text Rules

All copy is configured on the frontend. Copy varies by two dimensions: sheet state (expanded vs. collapsed) and time type (exact vs. end-of-slot).

4.6 Late Delivery Handling

If the actual delivery runs later than planned_delivery_time, the bottom sheet continues to display the original planned time and remains visible in its active state. No special late message is shown. The bottom sheet is only removed once the order reaches shipped status.

5. Decisions

# Question Decision
1 Multiple active orders Show only the next (soonest) delivery
2 API timeout / data unavailable Show nothing — hide the bottom sheet
3 App reopen mid-delivery Fetch fresh data immediately on reopen

6. External Courier — Business Rules

6.1 Key Differences from Farmy Internal Courier

Topic Internal Courier External Courier
Delivery time precision Exact time possible Always end-of-slot only
planned_delivery_time_is_fake true or false Always true
Map Yes, when en_route + courier assigned Never
Removal from homescreen When status = shipped When planned_delivery_time has passed

6.2 When to Show the Bottom Sheet

Same order status logic applies: show for complete orders, hide for canceled.

Removal condition differs: external courier orders are marked as shipped at 5am the day after the delivery day — this status cannot be used to hide the bottom sheet. Instead, the bottom sheet is removed as soon as planned_delivery_time has passed.

Condition Bottom Sheet Shown?
Order canceled No
Order complete + planned_delivery_time in the future or today Yes
Order complete + planned_delivery_time has passed No — removed from homescreen

6.3 Time Display Logic

planned_delivery_time_is_fake is always true for external courier. The time shown is always the end-of-slot deadline ("before [Time]"). Exact-time copy variants do not apply.

6.4 Map

Never shown for external courier deliveries.

6.5 Copy / Text Rules

All copy is configured on the frontend. Since planned_delivery_time_is_fake is always true, only the end-of-slot copy applies.
